P 动力学
========

P DynamicsIR 是侧层，不在 L5 到 L0 的降级链上。
它用交换契约描述连续演化：问题、请求、结果与能力。
本包构造、交换并检查这些记录，但不执行时间演化，也不调用求解器。
P 层不依赖电路模型；调用方须从 ``qaiji.core.physical`` 显式导入。
构造与检查的示例见 :doc:`/getting-started/physical`，完整接口见 :doc:`/api/physical`。

契约记录
--------

.. list-table:: P 层主要记录
   :header-rows: 1
   :widths: 22 78

   * - 记录
     - 内容
   * - ``Problem``
     - 站点与张量顺序、静态 Hamiltonian、驱动、
       环境（``closed``，或带 Lindblad 跳跃项的 ``markovian``）、
       初态、信号时间网格、参考系、近似列表与扩展。
   * - ``Request``
     - 一个 ``Problem``，加上输出时间、观测、执行策略和来源 ``Provenance``。
   * - ``Provenance``
     - 来源种类、可选的 ``program_ref``、设备与校准快照引用、逻辑比特到站点标签的
       基组映射，以及之前的变换记录。
   * - ``Result``
     - ``request_id``、输出时间、张量顺序、参考系、观测值与执行报告。
   * - ``Capabilities``
     - 消费者声明的 profile、最大维度、精度、所需扩展、输出种类与方法。

每类文档有固定的 schema，当前版本为 1.1，例如 ``qaiji.p.request/1.1``。
所有记录不可修改。

单位与张量顺序
--------------

输入端须显式声明单位。检查器不补充物理默认值。

.. list-table:: 物理量与单位
   :header-rows: 1
   :widths: 45 55

   * - 物理量
     - 单位或约束
   * - 时间与最大步长
     - ``ns``
   * - 静态 Hamiltonian 与驱动信号
     - ``rad/ns``
   * - 驱动算子与跳跃算子
     - ``1``，即无量纲
   * - Lindblad 速率
     - ``1/ns``，且不得为负

Hamiltonian 使用角频率，消费者不得再乘以 ``2π``。
Lindblad 项写成速率乘以耗散子。消费者的接口使用振幅形式时，须取速率的平方根；
本包不执行这项转换。

``tensor_order`` 决定张量积的顺序：最左的站点对应变化最慢的索引。
``sites`` 的记录顺序不能代替此字段。约化态按观测的 ``keep`` 顺序排列。
投影使用 ``V†ρV``，不重新归一化。

参考系
------

``frame`` 是显式的参考系标签，本包不自动转换参考系。``h0`` 与驱动始终按实验室系给出。

- ``frame="lab"`` 时，``rotation_freqs`` 必须为空。
- ``frame="rotating"`` 时，``rotation_freqs`` 给出每个站点的旋转频率。
  每个条目是 ``(站点 id, 频率)`` 二元组，频率单位为 rad/ns。
  条目按 ``tensor_order`` 排列，且覆盖全部站点。

近似列表含 ``rwa`` 时，消费者在该旋转系中丢弃反旋项。
``rwa`` 只能与 ``frame="rotating"`` 同用；结构检查拒收实验室系中的 ``rwa``。
旋转频率可以与漂移频率不同，差值作为失谐留在演化中。
消费者可以施加更严格的规则，例如要求旋转频率等于漂移频率。

旋转系中的态由实验室系的态变换得到：

.. math::

   \psi_r(t) = U_r(t)\,\psi(t), \qquad
   \rho_r(t) = U_r(t)\,\rho(t)\,U_r(t)^\dagger, \qquad
   U_r(t) = \exp\!\left(+i \sum_k \omega_k n_k t\right).

其中 :math:`\omega_k` 是站点 :math:`k` 的旋转频率；:math:`n_k` 是站点 :math:`k` 的
能级序号算符，对角元为 :math:`0, 1, \ldots, d_k - 1`。
:math:`t` 是问题时间轴上的绝对时刻，原点为 :math:`t = 0`，不是第一个信号边界。
初态是第一个信号边界时刻 :math:`t_0` 的旋转系态 :math:`U_r(t_0)\,\psi(t_0)`；
结果中的态是各输出时刻的旋转系态。回到实验室系时，用 :math:`U_r(-t)` 变换。
基矢与相位约定见 :doc:`conventions`。

时间网格
--------

``signal_edges`` 定义连续演化的区间。信号在每个区间内按零阶保持（ZOH）取常值。
内部区间左闭右开：内部边界时刻使用右侧的样本，终点沿用最后一个样本。
常值信号支持零时长问题；ZOH 信号要求非空的演化区间。

``output_times`` 是独立的输出网格，可以不落在信号边界上。
消费者须在请求的时刻输出结果，不得吸附时刻或重写时间标签。

交换与身份
----------

``dump_*`` 与 ``load_*`` 函数按严格 JSON 交换记录；数组可以内联，也可以作为附件。
这些函数拒绝未知字段、重复键与未知版本。恢复附件时须检查内容摘要；
这些函数不通过路径或 URL 读取附件。

全部 P 文档的 schema 版本为 1.1；当前版本的包不读取 schema 1.0 的文档。
扩展有各自的版本，例如 ``qaiji.p.bath`` 的 ``1.0``，与 schema 版本无关。

``problem_id`` 标识问题的内容；``request_id`` 还覆盖输出网格、观测与策略。
两者都基于规范字节计算，来源快照不参与这两项身份的计算。规范字节保留顺序和显式的物理字段。
相同内容得到相同身份；身份相同不表示物理正确，也不表示已证明物理等价。

分级检查
--------

调用方须显式选择检查级别。级别逐级包含：

1. ``transport``：严格 JSON、字段、类型、版本、数值编码与附件。
2. ``structure``：另查引用、形状、单位与时间网格。
3. ``physical``：另查能力、数值条件与资源预算。

检查报告的 ``complete`` 只表示所请求的级别已检查完。
低级别通过不等于高级别通过。调用方须读取报告的 ``diagnostics`` 和 ``unchecked``。
``require_valid`` 拒绝失败或未完成的报告。
检查器不裁剪、归一化或修复输入。
物理检查针对总算子验证 Hermitian 条件，不以逐项检查代替对总和的检查。
``check_result(request, result, ...)`` 按原请求检查结果。

当前的物理检查只支持 ``lab`` 参考系：

- 实验室系中的 ``rwa`` 在结构检查时以 ``INVALID_REQUEST`` 拒收。
- 旋转系请求（含或不含 ``rwa``）只认证到 ``structure`` 级；``physical`` 级检查返回
  ``UNSUPPORTED_CAPABILITY``。
- 结构检查核对 ``rotation_freqs`` 的站点与顺序，不核对数值。

物理检查无法识别按 GHz 写入（即少乘 ``2π``）的频率。
这类错误只能由消费者的检查或数值回环比对发现。

资源预算
~~~~~~~~

``CheckBudget`` 设置显式的资源上限。默认上限如下表。这些上限不代表对性能或内存占用的承诺。

.. list-table:: ``CheckBudget`` 的默认上限
   :header-rows: 1
   :widths: 60 40

   * - 资源
     - 默认上限
   * - 全局 Hilbert 维度
     - 64
   * - 数值工作槽位
     - 1048576
   * - 有理数更新次数
     - 1000000
   * - 分子或分母的位长
     - 16384
   * - JSON 字节数；附件字节数（各自计算）
     - 16777216
   * - JSON 嵌套深度
     - 32

预算不足时，报告含 ``RESOURCE_LIMIT`` 诊断；检查器不会静默跳过超出预算的检查工作并报告成功。

能力匹配
--------

``extract_requirements`` 从请求提取能力需求，``match_capabilities`` 检查完整的能力组合。
每个 profile 含 ``approximations``：需求列出请求的近似，能力列出允许的近似。
只有请求的近似都在允许集合中，且参考系相同时，才能匹配。
能力摘要不替代物理输入。匹配只说明消费者声明可以处理该请求，不证明求解结果正确。
执行策略固定或限定算法的选择；实际的选择须写入执行报告。

扩展
----

当前版本不提供 bath 求解器。问题可以在显式的必需扩展中携带 bath 数据，
编解码器保留这些数据。

扩展 ``qaiji.p.bath`` 的版本 ``1.0`` 有公开 schema，内容类型为
``application/vnd.qaiji.p.bath+json``。payload 含四个字段：

- 耦合算符：单位为 ``"1"`` 的 ``OperatorSum``，使用交换格式编码。
- 谱密度：``kind`` 取下列三个值之一。

  - ``drude_lorentz``：参数 ``lam`` 与 ``gamma``，都为正。
  - ``one_over_f``：参数 ``eta``、``w_lc`` 与 ``w_hc``，都为正，且 ``w_lc < w_hc``。
  - ``tabulated``：参数为一维 f64 数组 ``omega`` 与 ``J``。两者等长，至少 2 个样本。
    ``omega`` 从 0 或以上严格递增；``J`` 非负，且在 ``omega = 0`` 处为 0。

- 温度：:math:`k_B T/\hbar`，为正。
- PSD 约定：必填。当前只接受 ``frequency_axis`` 为 ``rad/ns``、``sides`` 为
  ``one_sided``、``fourier_measure`` 为 ``1/pi`` 这一组取值。

频率类参数与温度的单位都为 rad/ns。标量使用 binary64 十六进制字符串编码。

结构检查校验该 payload；bath 请求只认证到 ``structure`` 级。
消费者须在 ``required_extensions`` 中声明 ``("qaiji.p.bath", "1.0")`` 才能匹配。
一个问题可以带多个 bath 扩展，每个扩展独立描述一个库。

结构检查可以接受完整的不透明扩展。未知的必需扩展会使完整的物理认证被拒绝，
拒绝发生在稠密装配之前。本包不通过外部注册表补全扩展。

相关约定与层：基矢约定（:doc:`conventions`）、L5（:doc:`program`）。
层间连接见 :doc:`layer-relations`。
